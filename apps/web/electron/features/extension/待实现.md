## invoke / 宿主能力扩展

| 项 | 说明 | 参考 |
|----|------|------|
| `settings.get` / `settings.set` | 读写宿主 [`settings-store`](../settings/settings-store.ts)，需**白名单键**，避免 `apiKey` 等敏感项；与 `host.storage`（插件私有 KV）区分 | 五期 §D（建议未做）、六/七期备忘 |
| `authToken` 仅注入、不下发 `getContext` | 可选安全加固：`auth.read` 只走 webRequest 自动带头，context 不再带 `authToken` | 产品未选；当前保留 context + 自动注入并存 |

**现状**：已有 `storage.get/set`、`backend.health`、`window.openSettings`、`pet.*`、`recruitment.open` 等，见 [`extension-permissions.ts`](extension-permissions.ts)。

## 网络安全（增强项）

| 项 | 说明 | 参考 |
|----|------|------|
| `service` 子进程出站管控 | 本地 HTTP 代理 + `HTTP_PROXY`，与 UI allowlist 对齐；或平台级沙箱 | [插件网络 webRequest 计划](../../../../.cursor/plans/插件网络_webrequest_80b62f7f.plan.md)「不在本期」 |
| 响应体大小 / 超时统一限制 | 原 `extension.fetch` 有 5MB、30s；现由浏览器原生处理，宿主未限制 | 按需再加 |

**现状**：**仅插件 UI 窗**受 `webRequest` + allowlist + 主后端端口 SSRF 拦截；`service` 子进程出站**不受限**。

## 已不再需要单独实现（备忘归档）

以下在旧计划中出现，因架构调整**不必再做**：

| 原备忘 | 原因 |
|--------|------|
| `extension.fetch` 主进程代发 | 已移除，改为插件 UI 原生 `fetch` + [`extension-network-guard.ts`](extension-network-guard.ts) |
| 宿主代发 fetch 二进制 / multipart | UI 直接用浏览器 API；大文件可走 `serviceBaseUrl` |
| `extension.fetch` 与主应用 `request.ts` KV 统一 | 随 `extension.fetch` 移除而失效 |
