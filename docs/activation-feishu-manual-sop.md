# 激活运维 SOP · 飞书人工流转

> 装机员与发码管理员通过飞书审批单交接激活码。**纯人工流程，无代码自动化**。
> 镜像服务见 [签发服务镜像部署](./license-issuer-server-deploy.md)。

## 角色

- **装机员**：在目标机现场，跑 deploy、填设备码、取授权码装机。无私钥。
- **管理员**：在持私钥的机器上跑签发镜像服务出码、填回飞书。

## 飞书审批单需要的字段

在飞书审批定义里建一张单，至少两个字段：

| 字段 | 谁填 | 说明 |
|------|------|------|
| 设备码 | 装机员（发起时填） | 目标机 deploy 打印的序列号，如 `3E56-77F8-E917-9E20-7A30` |
| 授权码 | 管理员（出码后填回） | 镜像服务出的 `license_code`，一长串 |
| （可选）申请人 / 机器备注 | 装机员 | 台账留痕 |

## 完整流程

```
① 装机员跑 deploy → 看到设备码
② 装机员在飞书发起审批，填入设备码
③ 管理员看到单 → 用设备码跑镜像服务出码
④ 管理员把授权码手动填回飞书单的「授权码」字段
⑤ 装机员在飞书单看到授权码 → 复制
⑥ 放进目标机（文件 / 终端粘贴）→ deploy 再跑 → App 验签 → 激活
```

### ① 装机员：拿设备码
在目标机跑 `deploy.sh`，激活阶段会**醒目打印设备码**（也写进安装报告）。
未激活时 deploy 会提示「凭此码去飞书换码」。

### ② 装机员：飞书发起审批
新建审批单，设备码字段填上 deploy 打印的那串（带不带分隔符均可），提交。

### ③ 管理员：出码
在持私钥的机器上，调签发镜像服务（详见
[部署文档](./license-issuer-server-deploy.md)）：
```bash
curl -s -X POST http://<服务器>:8900/license/issue \
  -H "Authorization: Bearer <ISSUER_API_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"device_code":"<飞书单里的设备码>"}' | python3 -m json.tool
```
取响应里的 `license_code`。

### ④ 管理员：填回飞书
把 `license_code` 手动粘进该审批单的「授权码」字段（并批准/完成单子）。

### ⑤⑥ 装机员：取码装机
在飞书单看到授权码 → 复制 → 放进目标机：
- **文件通道**：写进 deploy 的授权码文件（`packages/activation.md` 等候选第一行）。
- **终端通道**：deploy 激活阶段提示时直接粘贴。

deploy 再跑一遍 → 写 `activation.json` → 数字员工 App 启动 `verify_license`
（设备绑定 + 过期校验）→ 激活生效。

## 要点

- 飞书在此**只是传话筒 + 台账**：人出码、人填回，无 API 写回、无轮询、无回调。
- 授权码绑定设备码：填错单/串机也无妨，目标机验签会 `device_mismatch` 拒绝。
- 私钥只在管理员的发码机器，永不进客户端/镜像层。
- 激活仅锁数字员工一个组件；hanhai-cli / 模型层不受此约束（roadmap）。

## 与自动化的关系

本 SOP 是**人工版**。若将来流转节点多、人工填回易错，可升级为
镜像服务出码后自动写回飞书字段（设计存档：
[飞书审批轮询 spec](./superpowers/specs/2026-06-17-feishu-approval-poller-design.md)，
未实施）。当前刻意保持人工，零代码维护成本。
