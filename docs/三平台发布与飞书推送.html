三平台发布与飞书推送

数字员工客户端 v0.1.x 的发布走 GitLab CI:推 tag → 三平台并行构建 → 自动推飞书。 本页上半部说明正常自动流程,下半部给出手动应急推送命令(当 CI 自动推飞书失败时,直接在打包机上补推,不必重打包)。

自动发布(正常路径)推 tag 即触发

本地或任意能 push 的环境里执行,GitLab CI 接管后无需值守。

1. 在 dev 上 bump 版本(apps/web/package.json)
# 把 "version": "0.1.x" 改成新版本号，提交、推 dev
git add apps/web/package.json
git commit -m "chore(release): bump version 0.1.x -> 0.1.(x+1)"
git push origin dev
2. 在同一提交上打 tag 并推送
git tag v0.1.(x+1)
git push origin v0.1.(x+1)
推完去 GitLab → 项目 → CI/CD → Pipelines 看新触发的那条。三个 job 同 stage 并行:
  • build:windows — 在 GQZN-01 上跑 build-windows.ps1 → 出 exe → 自动推飞书
  • build:linux — Mac mini 上 Docker 交叉构建 → 出 deb → 自动推飞书
  • build:macos — Mac mini 原生构建 → 出 dmg/zip → 自动推飞书
Linux 和 macOS 共用 mac-builder(concurrent=1),串行;Windows 独立机器并行。整体约 20~30 分钟。
每次都 bump 新版本号、打新 tag(0.1.15 → 0.1.16),不要重复使用同号 tag。GitLab 11.7 老服务器对强推 tag 不友好,换号最干净。
链接格式提醒(旧版 GitLab)

11.7 版的 pipeline URL 不含 /-/。如果飞书记录里的「流水线」链接打不开,把 /-/pipelines/ 改成 /pipelines/。
例:https://gitlab.bobandata.com/llm/digital-employee-client/pipelines/35009

手动应急推送

当某个 job 把包构建出来了、但飞书推送那一步失败(SSL/限流/网络抖动),不必重打包——直接在对应打包机上手动补推。

每次操作前先拉最新 publish-feishu.py,确保拿到今天磨出来的修复: SSL 钥匙串信任、HTTP Connection: close、分块上传 3 次重试、进度日志。
凭证 FEISHU_APP_ID / FEISHU_APP_SECRET 去 GitLab → 项目 Settings → CI/CD → Variables 复制(展开后点 Reveal value)。 Group 级变量在 group settings 里。

Windows exe GQZN-01

在 Windows 打包机 RDP 终端里跑。Python 用 yaoji 账户那个 64 位 3.11。

1. 进仓库目录 + 拉最新脚本
cd C:\Users\yaoji\Desktop\gitlabrunner\builds\Rr9JJ_VD\0\llm\digital-employee-client
git fetch origin
git checkout origin/dev -- scripts/ci/publish-feishu.py
2. 设凭证 + 看 exe
$env:FEISHU_APP_ID = "<粘贴>"
$env:FEISHU_APP_SECRET = "<粘贴>"
ls apps\web\release\*.exe
3. 推(把文件名换成上面看到的)
C:/Users/yaoji/AppData/Local/Programs/Python/Python311/python.exe `
  scripts/ci/publish-feishu.py "apps\web\release\BobanStaff-Windows-0.1.15-Setup.exe"

Linux deb Mac mini

在 Mac mini 上跑(Linux 构建出 deb 后留在 Mac mini 的仓库根 release/)。

1. 进仓库目录 + 拉最新脚本
cd /Users/yaojie/builds/aLK_hmfz-/0/llm/digital-employee-client

macOS dmg + zip Mac mini

和 Linux 在同一台 Mac mini,产物在 apps/web/release/。

1. 进目录 + 拉脚本(如果刚跑过 Linux 推送可跳过)
cd /Users/yaojie/builds/aLK_hmfz-/0/llm/digital-employee-client
git fetch origin
git checkout origin/dev -- scripts/ci/publish-feishu.py
2. 设凭证 + 看产物(同终端会话已 export 过可跳过)
export FEISHU_APP_ID="<粘贴>"
export FEISHU_APP_SECRET="<粘贴>"
ls -lh apps/web/release/*.dmg apps/web/release/*.zip
3. 推 dmg + zip(各一条记录)
python3 scripts/ci/publish-feishu.py \
  apps/web/release/BobanStaff-Mac-*-Installer.dmg \
  apps/web/release/BobanStaff-Mac-*-Installer-mac.zip

嫌"版本"列显示 local 不好看? 推之前临时设一下(只影响这次飞书记录里的版本号): 
export CI_COMMIT_TAG=v0.1.15   # Linux/Mac
$env:CI_COMMIT_TAG = "v0.1.15"  # Windows PowerShell

常见报错

SSL CERTIFICATE_VERIFY_FAILED (Mac 上)

企业网关 TLS 中间人,Python certifi 没自签根证书。脚本已支持从 Mac 钥匙串自动导出根证书。 如果还失败,设环境变量指向 IT 给的根证书 PEM: 

export FEISHU_CA_BUNDLE=/path/to/company-root.pem

EOF occurred in violation of protocol

大文件长连接被代理切断。脚本已加 Connection: close + 3 次重试。 如果连续失败,大概率是飞书侧限流——等几分钟再试。

⏭️ 未配置 FEISHU_APP_ID / FEISHU_APP_SECRET

凭证没 export 上,检查环境变量。
