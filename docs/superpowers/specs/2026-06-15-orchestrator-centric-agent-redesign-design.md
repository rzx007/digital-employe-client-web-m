# 总管中心 Agent 重构：弱化员工、唯一入口、组队后台、经验闭环

> 设计稿 · 2026-06-15
> 范围：整个产品的 Agent 形态级重构。把"员工中心"（员工各自有工作目录/单聊/群聊、是一等对话对象）
> 转为"总管中心"（总管是唯一入口，员工退居幕后作为会成长的能力单元）。
> 灵感参照：Claude Code（按复杂度自动 fan-out 后台子任务）+ Hermes agent 的学习闭环（经验沉淀）。

---

## 0. 背景与动机

### 0.1 现状（员工中心）

员工是一等公民：各自有工作目录（产物/上传，刚升到员工级）、私有技能与记忆、能被用户**直接单聊**，
还能组**群聊房间**协作（组长 + DAG 派活 + 结论回流）。总管只是其中一个特殊"员工"
（id=`orchestrator`）。

会话地基已完成事件溯源重构（单聊 + 群聊统一在 event_log 上：snapshot / live tail / 断线 resume /
HITL 生命周期 / 子任务进度面板）。

### 0.2 这次要变成（总管中心）

四个支柱：

1. **唯一入口**：用户只跟总管对话，不再直接点开员工聊天。
2. **单一共享工作区**：取消"员工各自的工作目录"，只在总管开一个共享工作目录，全队读写、互相看得见产物。
3. **Claude Code 式自动拆活**：用户提一个需求，总管按复杂度自动 fan-out 一堆子任务，**真异步**在后台跑。
4. **员工 = 经验沉淀**：员工概念保留，但不再是对话对象，而是 Hermes 式学习闭环里"越用越厚"的能力单元；
   总管派活时挑合适的来用，用完它学到东西。

### 0.3 与既有红线的关系

记忆里红线①"前端 UI 尽量不删"是针对**会话地基重构**阶段（换地基不砍功能）。本次是**有意的产品级形态转向**，
用户明确"当新项目做、不用束手束脚"，因此红线①在本次被这条新决策覆盖：员工单聊/群聊作为**对话入口**退场，
降级为只读成长面板。底层干净地基（事件溯源/进度面板/准入）继续复用。

## 1. 顶层模型

### 1.1 三层结构与一次请求的生命周期

```
你 ──对话──▶ 总管（唯一入口，唯一对话面）
                  │
                  ├─ 判断复杂度：简单活自己干；复杂活 → 组队
                  │
                  ├─ 组队：决定需要哪些角色 → 每个角色「复用优先于新建」
                  │         ├─ 有匹配的老员工 → 拉来用（带经验加成）
                  │         └─ 没有 → 现造一个新员工（干完即持久化进名册）
                  │
                  ├─ 派活：给每个员工一个后台子任务（真异步，派完即返回）
                  │
                  ▼
        共享办公桌（总管的一个工作目录，全队读写、互相看得见产物）
                  │
   员工A后台跑 ┐  │  ┌ 员工B后台跑     ← 各自带「私有大脑」(技能/记忆)入场
   员工C后台跑 ┘  │  └ …               ← 进度逐字回流到「子任务面板」
                  │
                  ├─ 回流：谁干完，结论+产物回到总管会话（task.completed/failed 事件）
                  ├─ 再入整合：总管被事件唤醒，把回流结果整合进对话，交付给你
                  │
                  ▼
        经验沉淀：参与的员工各自把这次的「经验」沉回自己的私有大脑
```

### 1.2 界面：三个面，砍掉两个旧的

| 面 | 作用 | 来源 |
|----|------|------|
| **总管对话面** | 唯一入口，你只在这聊 | 复用现有事件溯源单聊视图（对话对象换成总管） |
| **子任务/团队面板** | 后台子任务实时进度（Claude Code Background tasks 风格） | 已有，复用 |
| **员工成长面板（只读）** | 看每个员工攒了啥技能/记忆/历史产物/被派过的活 | **新增** |
| ~~员工单聊~~ | — | **退场**（降级为只读成长面板） |
| ~~群聊房间~~ | — | **退场**（编排"教训"留下，UI 与群专属胶水删） |

### 1.3 三条贯穿原则

1. **总管是唯一对话面**——员工永不直接对话，只在幕后被派活、被查看。
2. **共享桌 + 私有脑**——产物全队共享一个目录；技能/记忆每个员工私有，是成长的家。
3. **涌现式成长**——名册不预定义、不用用户当 HR，从真实项目里长出来；复用优先于新建
   （同时天然防膨胀，闲置的靠定期复盘退休/合并）。

## 2. 员工模型与名册

### 2.1 员工是什么

员工 = 一个**持久的、会成长的能力单元**，持有：私有技能（`skills/`）、私有记忆（`memories/`）、
情景流水（`journal/`）、能力画像（`profile.md`）。它**不再有对话入口、不再有私有工作目录**
（产物落共享桌）。

### 2.2 名册生命周期：涌现式持久个体

- **涌现**：总管组队现造角色 → 角色干完活 → **持久化为员工进名册**。
- **复用优先于新建**：总管组队时先按能力画像匹配老员工，匹配上就复用（带经验加成），匹配不上才新招。
- **成长落在个体**：员工#42"越用越强"，与"只读成长面板看个体成长"一致。
- **防膨胀**：定期复盘（§3.4 librarian）退休长期闲置、合并近重复员工。

### 2.3 非目标

- 不做用户手动 HR 管理（招聘/解雇 UI）作为主路径——名册自然涌现；手动干预作为后续可选增强。
- 不做"项目团队"作为持久组织单位——持久的是**个体**，团队是每次请求的临时编组。

## 3. 学习闭环（员工怎么越用越厚）

### 3.1 经验的两种形态 + 存哪（都在员工私有大脑）

```
员工私有大脑  $BRAIN/<employee-id>/
├── journal/      ← 情景记忆（episodic）：流水账，便宜、always-on
├── skills/       ← 可复用技能（procedural）：SOP/模板/打法，贵、信号才提炼
├── memories/     ← 零散教训/偏好：信号才写
└── profile.md    ← 能力画像（自动维护，见 §3.5）
```

| 形态 | 是什么 | 写入成本 | 触发 |
|------|--------|---------|------|
| **情景记忆** journal | "这类活我上次怎么干、产物在哪、成没成" | 近乎免费（只记日志，不调模型） | 每子任务完成，自动 |
| **可复用技能** skills | "这类活的标准打法/模板" | 贵（要 critic 提炼） | **信号**触发 |
| **零散教训** memories | "用户偏好这样""那坑别再踩" | 贵 | **信号**触发 |

### 3.2 四个环节

```
①捕获(自动·免费) ─▶ ②提炼(信号·后台critic) ─▶ ③复盘(定期·后台librarian) ─▶ ④回喂(派活时)
```

- **①捕获**：子任务一结束，后端**自动**往该员工 `journal/` 追加一条结构化流水。捕获字段须**覆盖
  §3.3 所有信号的判定来源**：任务摘要、用了哪些工具/技能、成败、产物路径、**耗时、（可得时的）成本/token**
  ——这样"耗时/成本异常"若纳入信号集（§7 Q3）有数据可依。**不调模型**，近乎零成本。
- **②提炼**：有信号才跑——一个**独立的轻量 critic 在后台异步**读相关 journal + 信号，提炼成
  skill 或 memory。不占用户等待、不污染总管主上下文。
- **③复盘**：后台 librarian 周期性（或大脑超阈值时）合并重复、删过时、**退休/合并闲置员工**
  （= 名册防膨胀），并更新各员工 `profile.md`。参照本仓所在 Claude Code 环境的 consolidate-memory 模式。
- **④回喂**：见 §3.5。

### 3.3 "什么算信号"（只有强信号触发昂贵提炼）

| 信号 | 含义 | 提炼成什么 |
|------|------|-----------|
| **用户纠正** | 用户在总管对话里指出"不对，应该…" | memory（软）——最强信号 |
| **失败后成功** | 子任务炸了→重试→成了，这个 diff 就是教训 | memory："这么做会炸，那么做才行" |
| **重复模式** | 同一打法跨任务出现 N 次，被验证 | skill（硬）——只有验证过才晋升技能 |
| **显式记住** | 用户/总管说"记住这个打法" | skill 或 memory |
| **总管验收返工** | 总管整合时判定某子任务要返工 | memory：返工原因 |

**关键防坑**：单次成功**不**直接晋升技能（防止把侥幸当真理）——单次信号只进 memory（软知识），
只有**重复出现/被验证**才晋升 skill（硬知识）。这是"信号闸门"的真正价值。

### 3.4 防坑小结

- 不在用户等待路径上跑反思（critic/librarian 全后台异步）。
- 不让单次轨迹直接造硬技能（防 fluke）。
- 复盘自清理，防记忆库与名册腐化/膨胀。

### 3.5 统一概念：`profile.md`（一物三用）

每个员工自动维护一份简短能力画像（我擅长什么、干过哪类活、踩过哪些坑），由复盘环节更新。一处产出，三处消费：

1. **路由**：总管组队时读各员工 profile，决定派给谁/是否新招——**路由本身就是检索**。
2. **回喂**：派中的员工，`skills/` 自动加载常驻 + 一个`搜记忆`工具按需查 journal/memories。
3. **成长面板**：只读面板头条 = profile + 底下技能/记忆/历史。

### 3.6 学习闭环非目标（YAGNI）

- 不做向量库/embedding 语义检索（先用 profile 摘要 + 关键词/工具检索；昇腾本地省得养 embedding）。
- 不做跨员工自动经验传染（好打法靠复盘半自动提升，不自动扩散）。

## 4. 异步执行引擎（干净重写）

### 4.1 引擎核心概念（极简）

```
总管接需求 → 产出一个 Plan
   Plan = 一组 Task，每个 Task 可选 depends_on（最小依赖，不是群聊那套 DAG 胶水）
        Task#1 后端接口  ─┐
        Task#2 前端页面   ├─ depends_on: 后端接口
        Task#3 测试       └─ depends_on: 后端+前端

调度器：依赖满足的 Task 就发车；受 registry 准入 + 信号量限并发（护昇腾单卡）
Task 状态机：queued → running → done/failed/interrupted   ← 持久化（event_log + TaskExecutionLog）
            （interrupted = 跨重启时未完成被标中断，见 §4.4；是状态机的一等枚举，不是临时态）
```

> 依赖是"组队开发项目"绕不开的（前端依赖后端接口），但只做**最小 `depends_on`**，
> 不搬群聊的组长/成员/房间账。

### 4.2 总管再入整合（★ 本次真正的新难点）

轮内并行天然在同一轮整合；真异步里总管那一轮**早已返回**，子任务后台跑完后总管需"醒来"整合。

**方案：事件驱动唤醒 + 批量节流（复用既有 EventLogNotifier 跨请求通知，即 P2a 能力）**

```
子任务完成 → 往总管会话 event_log 写 task.completed（结论摘要 + 产物路径）
                  │
       总管协调器在监听（live tail）
                  │
       一批/关键任务完成 → 触发一个「总管整合轮」（系统发起的 assistant turn，非用户消息触发）
                  │
       总管读回流结果 → 整合 → 流式发给用户
                  │
       体验：总管"主动回来"：「后端做完了，这是接口文档；前端我接着派了」
```

**关键新能力**：总管会话能被**外部事件**（而非只有用户消息）触发新 turn。这是以前没有的，
也是 bug 会聚集处（如同此前 HITL 是复杂度热点）。

**防风暴**：整合轮**串行 + 节流**，一次只处理一个整合，攒一批再醒，不每个子任务都打断用户。

**可调旋钮**：逐个回流（碎但实时）vs 攒齐回流（整但慢）。默认攒关键里程碑。

### 4.3 子任务无澄清；HITL 只在总管层

子任务拿到**自包含派单**，自主跑到底，**不回头问**（与既有 `dispatch_directive` 约定一致）。

```
两处澄清，都在总管层（子任务全程不阻塞）：
① 派活前  总管拆活时若需求本身模糊 → 在对话里先问你 → 问清再派
            （= 现有总管会话 HITL，照用）
② 回流后  子任务若信息不足 → 把「我做了X假设」或「缺Y信息」写进它的【结果】带回
            → 总管再入整合时自行决定：用假设继续 / 回头问你 / 补料重派
            （子任务报告的是"结果"，不是阻塞中断）
```

**收益**：异步引擎**不接**子任务 HITL；再入整合只处理"完成/失败"两种终态，不处理"中途被打断要人答"，
bug 面更小。HITL 复杂度全部留在总管对话面（已啃透）。

子任务派单原则：**自包含 + 自主决策 + 缺啥写进结果带回，绝不阻塞等人**。

### 4.4 两个边角（沿用现有约定）

- **共享桌并发写**：每个子任务用自己的子目录/文件名，靠命名约定避免撞名（沿用 parallel-subtasks 约定），
  第一版不做文件锁（YAGNI）。
- **跨重启存活**：单机桌面关了 app，未完成任务标"中断"，总管一键重派（自动续跑作为后续增强，
  先不碰半截状态的复杂性）。

## 5. 目录模型：共享桌 + 私有脑

```
工作产物（共享桌）：单一总管级共享工作目录，全队读写
   <artifacts_root>/orchestrator-workspace/         ← $ARTIFACTS_DIR（= cwd，全队共享）
       ├── task-<id>/ …                             ← 各子任务自己的子目录（防撞名）
       └── …

员工私有脑（不共享，成长的家）：
   $BRAIN/<employee-id>/{journal, skills, memories, profile.md}
```

- **从员工级工作空间收回为单一共享**：这是对"刚做的员工级工作空间"作用域的回收——产物不再按员工/会话
  分叉，统一落总管共享桌。（去虚拟路径的真实路径 + env 注入机制不变，只改作用域。）
- **私有脑保留并强化**：技能/记忆从"员工级"延续，新增 journal/profile，成为学习闭环载体。
- **沙箱**：写 = 共享桌（+ 自己子目录）；读 = 共享桌全树 + 自己私有脑。员工 A 读不到 B 的私有脑（成长私有）。

## 6. 旧系统退场与复用边界（给既有投入找归宿）

| 处置 | 内容 |
|------|------|
| **照留复用** | event_log / snapshot / live tail / 断线 resume / EventLogNotifier；总管对话面（= 现单聊视图换对象）；子任务进度面板；registry 准入 + 子任务信号量；去虚拟路径的真实路径 + env 注入 |
| **退场删除** | 员工单聊入口（→ 只读成长面板）；群聊房间 UI；群专属编排（组长/成员/DAG/@派活/房间账 room ledger） |
| **新建** | 总管组队引擎（Plan + 最小依赖 + 调度 + 再入协调器）；员工成长面板（只读）；学习闭环（journal 捕获 / critic 提炼 / librarian 复盘 / profile 维护）；工作目录回收为单一共享 |

**迁移策略（与"当新项目做"一致）**：新模型为唯一系统，不做老数据复杂搬迁兼容。
**存量员工平滑纳入新名册**（它们本就有技能/记忆 = 现成的脑）；存量会话数据保留只读或归档。

## 7. 开放问题（评审/实现前定夺）

- **Q1 再入整合粒度默认值**：默认"攒关键里程碑"还是"逐个回流"？暂定攒里程碑 + 旋钮可调（§4.2）。
- **Q2 总管自主回答 vs 转用户的边界**：子任务回流报"缺信息"时，总管何时自己拍、何时回头问你？
  暂定：能从已有上下文合理推断就自主；涉及不可逆/关键决策才回头问。
- **Q3 信号集是否够**：§3.3 五类信号是否完整？是否需要"耗时异常/成本异常"作为信号？暂定先上五类。
- **Q4 跨重启**：未完成任务"标中断 + 一键重派"是否够？还是首版就要自动续跑？暂定标中断重派。
- **Q5 名册手动干预**：是否首版就给"查看/退休员工"的只读+轻操作面板，还是纯自动？
  暂定成长面板只读 + 退休靠自动复盘，手动干预后置。
- **Q6 总管自身是否也走学习闭环**：总管作为特殊 agent，要不要也有 journal/profile 自我成长？暂定要（一致）。

## 8. 受影响范围（实现时细化为分相位计划）

**服务端**：
- 新增总管组队引擎：Plan/Task 模型、依赖调度器、再入整合协调器（监听 event_log → 触发整合轮）。
- 总管会话支持"外部事件触发 turn"（非用户消息驱动的 assistant turn）。
- 子任务派单走真异步后台执行（复用 `_run_agent_background` / registry / 信号量），派完即返回。
- 学习闭环：journal 自动捕获写入点（子任务终态）、后台 critic（信号触发提炼）、后台 librarian
  （周期复盘 + profile 维护 + 名册退休/合并）。
- 目录作用域：员工级工作空间 → 单一总管共享桌；env 注入调整；沙箱按"共享桌 + 私有脑"重解析。
- 退场：群专属编排（组长/成员/DAG/@派活/房间账）、员工单聊/群聊对话入口后端支撑。

**前端**：
- 总管对话面：复用事件溯源单聊视图，接 task.completed/failed 再入整合呈现。
- 子任务/团队面板：复用现有，接新引擎事件。
- 新增员工成长面板（只读）：profile + 技能/记忆/历史产物/被派记录。
- 退场：员工单聊入口、群聊房间视图。

**测试**：
- 引擎：Plan 依赖调度、并发受限、状态机持久化、断线/重启恢复。
- 再入整合：事件驱动唤醒、整合轮串行+节流、不打断风暴。
- 学习闭环：捕获 always-on、信号触发提炼、单次不晋升技能、复盘合并/退休、profile 回喂路由。

- 退场回归：删群专属编排后无残留引用。

## 9. 非目标（本设计明确不做）

- 不做跨进程/远程后台长任务（Agent Protocol 部署）——后台 = 同进程异步。
- 不做向量库语义检索（§3.6）。
- 不做跨员工自动经验传染。
- 不做"项目团队"持久组织单位（持久的是个体）。
- 不做用户 HR 式名册管理为主路径（涌现优先）。
- 不做子任务 HITL（子任务无澄清，§4.3）。
- 不做老数据复杂搬迁兼容（新模型新起，§6）。

## 10. 与既有事件溯源地基的衔接（关键复用点）

- **总管再入整合**复用 P2a 的 `EventLogNotifier` 跨请求通知 + live tail。
- **子任务进度**复用既有"并行子任务面板（Claude Code 风格）+ 逐字实时进度"。
- **断线/重启恢复**复用 snapshot + Last-Event-ID resume。
- **HITL（仅总管层）**复用已啃透的事件溯源 HITL 生命周期。
- **真实路径 + env 注入**复用去虚拟路径成果，仅改作用域为单一共享桌。
