## 2. admin 后台联调（看板）

admin 只有一个 `/actus` 代理。临时把它拆成两条：`/digital` → 本地 actus、其余(含 `/yc` 登录) → 真实平台。

改 `digital-employee-admin/vite.config.ts` 的 `server.proxy`（**测完还原**）：
```ts
proxy: {
  // /digital/* → 本地 actus(:8000)，剥掉 /actus/digital → /api/v1
  '/actus/digital': {
    target: 'http://localhost:8000',
    changeOrigin: true,
    rewrite: (path) => path.replace('/actus/digital', ''),
  },
  // /yc/* 及其余 → 真实平台（登录、角色菜单）
  '/actus': {
    target: 'http://10.172.246.179:5002',
    changeOrigin: true,
    rewrite: (path) => path.replace(/^\/actus/, ''),
  },
},
```
`cd digital-employee-admin && pnpm dev` → 浏览器开 3334/3359 → 用 **menuid=1 的管理员账号**登录 → 菜单「活跃度统计」。

> 规则：**`/yc/*` → 5002（鉴权）；`/digital/*` → 本地 :8000（统计/技能数据）**。

## 3. 客户端联调（产生真实埋点）

客户端埋点发往 `/digital/api/v1/analytics/events`。两种方式二选一：

### 方式 A · 桌面版 Electron（推荐，最接近真实）
Electron 下 `baseURL` 固定走 apps/server(34567)，vite 代理不生效。靠 **apps/server 的环境变量**把 analytics 转发目标改到本地 :8000：

```bash
cd D:\space\code\boban\digital-employee-client\apps\web
# Git-bash 必须带 MSYS_NO_PATHCONV=1，否则 /api/... 路径会被转成 Windows 路径！
MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*' \
  ANALYTICS_BASE_URL=http://localhost:8000 \
  ANALYTICS_EVENTS_PATH=/api/v1/analytics/events \
  pnpm dev:app
```
> 原理：apps/server 的 analytics 转发基址 `ANALYTICS_BASE_URL` 默认=平台地址；这里 env 覆盖成本地 :8000。登录仍走平台不受影响。这是 `apps/server/src/core/config.py` 里预留的覆盖点（生产不设该 env 即回归默认，无副作用）。

### 方式 B · 浏览器版（轻量）
改 `apps/web/.env`：`VITE_USE_ACTUS_PROXY=true`；
改 `apps/web/vite.config.ts` 的 `server.proxy`，在 `/actus` 前加一条（**测完还原**）：
```ts
"/actus/digital/api/v1/analytics": {
  target: "http://localhost:8000",
  changeOrigin: true,
  rewrite: (path) => path.replace("/actus/digital", ""),
},
```
然后 `pnpm dev`（3399）。需 apps/server(34567) 已起（`pnpm dev:server`）。

### 触发各类事件
- **登录** → `login`
- **启动** → `app_open`
- **技能市场点开/装技能** → `skill_view` / `skill_install`
- **对话里让 AI 用某技能**（如让员工用 html-ppt 做 PPT）→ `skill_invoke`（按技能名，含本地技能）

## 5. 关键设计备忘

- **统计一律按 `skill_name` 聚合**，不依赖 skill_id（客户端多为本地技能，无服务端 id）。
- **显示名 `name`（如"汪亮"）不在 token 里**，由客户端登录后写 `localStorage.displayName`，埋点随 `extra.name` 上报；`username`（登录名）由服务端从 token 解析。
- **skill_invoke = 对话里真正执行**：在 `apps/web/src/hooks/use-classified-message-blocks.ts` 里，回复结束后从「技能探索」块的文件路径提取技能名上报（本地技能路径形如 `…\employees-skills\<id>\skills\<技能名>\SKILL.md`），按 `messageId:skillName` 去重。
- **常驻代码（非测试，需保留/提交）**：actus 的 `models/analytics.py`+`api/v1/analytics/`+迁移；客户端 `apps/web` 埋点 + `apps/server` 的 analytics 转发路由(`analytics_api.py`/`config.py`)；admin 的 `api/analytics.ts`+`pages/activity`+菜单项。
